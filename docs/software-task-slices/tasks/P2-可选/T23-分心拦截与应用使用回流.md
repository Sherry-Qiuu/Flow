# T23 · 分心拦截与应用使用回流

> 工作流：**手机管控**（PHN）・优先级 **P2**・规模 **L**（3 人日）

| 字段 | 内容 |
|---|---|
| 任务 ID | `T23` |
| 工作流 | 手机管控（`PHN`） |
| 优先级 | P2 |
| 规模 | L / 3 人日 |
| 前置依赖 | `T18`、`T22` |
| 需协同 | `T21` |
| 建议角色 | 移动端 / 后端 |

## 1. 目标

更进一步：知道手机上到底用在哪了，并能在关键时刻拦一下。

## 2. 需求依据

- **SR-13** — 用户私人定制使用时长，为了防止用户的注意力被手机的其他应用分散（P31）
- **SR-15** — 减少分心的次数（P34）

## 3. 输入 / 输出

**输入**

- T22 局域网通道
- T18 画像口径

**输出（可交付物）**

- Android 轻量伴侣 App（或明确放弃该路径的说明）
- 使用数据回流与 Top App 统计
- P2 增强的边界说明

## 4. 工作内容

- [ ] 现实约束先说清楚：Linux 设备无法直接读取手机 App 使用数据，必须有手机端配合
- [ ] 方案 A（推荐）：Android 伴侣 App，用 UsageStatsManager 采集各应用前台时长，通过局域网 POST 到设备（只传包名 + 时长，不传内容）
- [ ] 方案 B（不做 App）：只做“契约 + 归位 + 坦白”（即 T21 + T18），用用户自述替代精确数据
- [ ] iOS：系统不开放该权限 → 只提供“屏幕使用时间”截图识别，或明确告知不支持
- [ ] 能力：分心时段统计、Top5 应用时长、到点前 1 分钟轻提醒
- [ ] 隐私：可一键关闭采集；关闭后设备侧不再接收任何使用数据
- [ ] 定位：明确标注 P2 增强，不阻塞主链路，资源紧张时整块砍掉也不影响演示

## 6. 验收标准（Definition of Done）

- [ ] 伴侣 App 上传后设备能看到 Top5 应用时长
- [ ] 关闭授权后设备不再接收任何使用数据
- [ ] iOS 路径给出明确说明，而不是静默失败
- [ ] 该任务未完成时，主链路（T21）功能完全不受影响

## 7. 风险与降级

- 权限门槛高（需用户手动授予“使用情况访问”）→ 首次引导必须图文清楚
- 投入产出比低 → 先做 T21，把这块当加分项
- 隐私敏感 → 所有采集默认关闭，必须用户显式开启

## 8. 提示

> 如果时间紧，直接砍掉这一条，把 T21 的语气打磨好，情绪价值反而更高。
