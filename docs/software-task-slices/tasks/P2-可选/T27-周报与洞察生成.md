# T27 · 周报与洞察生成

> 工作流：**数据与洞察**（DAT）・优先级 **P2**・规模 **M**（1.5 人日）

| 字段 | 内容 |
|---|---|
| 任务 ID | `T27` |
| 工作流 | 数据与洞察（`DAT`） |
| 优先级 | P2 |
| 规模 | M / 1.5 人日 |
| 前置依赖 | `T12`、`T26` |
| 需协同 | `T05`、`T16`、`T18` |
| 建议角色 | AI / 后端 |
| 当前状态 | 未开始 |
| 子任务数 | 3 项（见第 5 节） |

## 1. 目标

每周给用户一份“你这周其实做了很多”的温和总结，而不是一张批判性成绩单。

## 2. 需求依据

- **SR-16** — 刻画用户形象，鼓励用户持续减少分心（P35）
- **SR-09** — 用即时正反馈对抗“做了也没用”的无力感（P24）

## 3. 输入 / 输出

**输入**

- T26 metrics_daily
- T12 LLM 通道

**输出（可交付物）**

- 周报内容生成（模板 + LLM 润色）
- 3 屏卡片式呈现
- 导出为图片 / 文本

## 4. 工作内容

- [ ] 触发：每周日 20:00 自动 + 用户主动说“看看这周”
- [ ] 内容：完成了多少步、最专注的时段、分心趋势、连续天数、一个小建议
- [ ] 呈现：3 屏卡片（可语音翻页），每屏一句话 + 一个数字
- [ ] 生成：模板优先，LLM 只做润色；禁止比较式（“比上周少”）、禁止“落后/欠账”类词汇
- [ ] 无数据周的友好文案：不显示 0% 完成率，改为“这周你先歇了歇，下周可以从一件小事开始”
- [ ] 导出：生成 PNG 或文本存到 data/exports/，可后续经 T22 传到手机
- [ ] 降级：LLM 不可用时纯模板也能出完整周报

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

| 子任务 | 名称 | 产物 | 完成判据 | 人日 |
|---|---|---|---|---|
| `T27.1` | 模板与取数 | `app/analytics/weekly.py` | 无数据周也能出友好文案，不显示 0% 完成率 | 0.5 |
| `T27.2` | LLM 润色与词表 | `app/analytics/weekly.py` | 只改措辞不换骨架；禁用比较式与“落后/欠账” | 0.5 |
| `T27.3` | 三屏卡片与导出 | `ui/src/pages/Weekly + export` | 3 屏讲完、可语音翻页；导出 PNG/文本可打开 | 0.5 |

**小计 1.50 人日**

## 7. 实现要点

```
三屏结构：

    1) 完成了什么     "这周你完成了 27 个小步"
    2) 你在什么时候最好 "最专注是 20:00–21:00"
    3) 一个下周期望     "下周试试每天三个小步"

模板出骨架，LLM 只改措辞；LLM 不可用直接上模板。
无数据周不显示 0%，改写“这周你先歇了歇”。
```

## 8. 验收标准（Definition of Done）

- [ ] 无数据周也能生成友好文案，不出现 0% 完成率这种判定式展示
- [ ] 3 屏内讲完，可语音翻页，每屏停留时间可配置
- [ ] 导出文件可正常打开阅读
- [ ] 文案通过“无指责词”检查
- [ ] LLM 不可用时仍能产出完整周报

## 9. 风险与降级

- LLM 生成的总结过度热情显得假 → 保留模板骨架，只让它改措辞

## 10. 提示

> 把周报当成产品的“毕业答辩”：它要能用三个数字说清楚“这个产品真的帮到我了”。
