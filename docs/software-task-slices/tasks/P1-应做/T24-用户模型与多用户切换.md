# T24 · 用户模型与多用户切换

> 工作流：**账号与多用户**（USR）・优先级 **P1**・规模 **M**（2 人日）

| 字段 | 内容 |
|---|---|
| 任务 ID | `T24` |
| 工作流 | 账号与多用户（`USR`） |
| 优先级 | P1 |
| 规模 | M / 2 人日 |
| 前置依赖 | `T10` |
| 需协同 | `T05`、`T25` |
| 建议角色 | 后端 / 产品 |

## 1. 目标

一台设备认识宿舍/家里的每个人，各有自己的计划和习惯。

## 2. 需求依据

- **SR-21** — 多用户为追加需求（产品文档未写，按你的选择纳入范围）。

## 3. 输入 / 输出

**输入**

- T10 数据层
- T05 设置页

**输出（可交付物）**

- 用户创建 / 选择 / 切换
- 会话冻结与恢复
- 权限分级（管理员 / 普通用户）

## 4. 工作内容

- [ ] 创建：首次开机向导（名字、称呼、作息、目标），也可语音创建
- [ ] 识别与切换：MVP 用“手动选择 + 默认最近使用者”，设置页可切换；P2 加声纹（resemblyzer）或 NFC 卡
- [ ] 会话隔离：切换用户时冻结当前用户的执行态（当前步骤、计时、草稿），切回时恢复现场
- [ ] 权限：管理员可改设备设置、删用户；普通用户只能管自己的任务与偏好
- [ ] 表现：待机页显示当前用户头像/称呼与主题色
- [ ] 删除：级联清理该用户全部数据，二次确认

## 6. 验收标准（Definition of Done）

- [ ] 3 个用户各自的任务、计划、提醒完全隔离，交叉测试无泄漏
- [ ] 切换用户在 3 秒内完成，且对方正在执行的步骤能恢复
- [ ] A 的提醒不会在 B 的会话中播报
- [ ] 删除用户需二次确认，且数据级联清理干净
- [ ] 新用户首次进入有向导，不会看到上一个人的任务

## 7. 风险与降级

- 声纹识别在小样本下不准 → 默认手动切换，声纹只做“猜你是谁”的建议
- 切换过于频繁打断心流 → 切换要有明确确认，不做静默自动切换

## 8. 提示

> 多用户最容易被低估的是“数据隔离”而不是“切换界面”。隔离要靠 DAO 层的强约束，不能靠程序员自觉。
