# T18 · 分心坦白与用户画像统计

> 工作流：**情绪与激励**（EMO）・优先级 **P1**・规模 **M**（2 人日）

| 字段 | 内容 |
|---|---|
| 任务 ID | `T18` |
| 工作流 | 情绪与激励（`EMO`） |
| 优先级 | P1 |
| 规模 | M / 2 人日 |
| 前置依赖 | `T10`、`T21` |
| 需协同 | `T17`、`T23`、`T27` |
| 建议角色 | 后端 / 产品 |

## 1. 目标

鼓励用户说出“我刚才刷手机了”，把分心变成可改善的画像，而不是一次羞耻。

## 2. 需求依据

- **SR-15** — 鼓励用户坦白在手机上分心的时刻，按照用户喜好/习惯合理设置休闲娱乐时间：我们希望的不是一次增加工作/学习时间，而是减少分心的次数（P34）
- **SR-16** — 鼓励用户坦白在手机上分心的时刻，刻画用户形象，鼓励用户持续减少分心（P35）

## 3. 输入 / 输出

**输入**

- T21 手机使用契约数据
- T10 数据层
- T06 语音输入

**输出（可交付物）**

- 坦白入口（语音 / 手势 / 待机页）
- 画像统计（时段、触发、恢复时间）
- 非评判式反馈文案

## 4. 工作内容

- [ ] 坦白入口要极低摩擦：说“我刚才分心了”一句即可记录；待机页长按/手势也可；绝不弹窗质问
- [ ] 记录字段：时间、时长（估算）、用途（学习/休闲/不清楚）、情境（刚开始/卡住了/深夜）
- [ ] 口径：只看“次数与趋势”，不做当日对错评判、不设惩罚
- [ ] 画像：分心高峰时段、常见触发场景、平均回到任务的时间、休闲时间实际 vs 计划
- [ ] 反馈：周维度下降 → 明确肯定；上升 → 只陈述事实 + 给一个“小实验”建议（比如换个位置坐）
- [ ] 娱乐时间建议：按历史把休闲时长排进计划，而不是从学习时间里挤
- [ ] 口径统一：与 T21 的 phone_sessions 使用同一套时间定义，避免两个数字打架

## 5. 接口契约

```
# 事件：distraction.logged {at, minutes, purpose, context}
# 统计接口：GET /api/insights/distraction?range=7d
# → {count, total_minutes, peak_hours: [...], top_contexts: [...], avg_recovery_min}
```

## 6. 验收标准（Definition of Done）

- [ ] 一次坦白记录在 3 秒内完成，不需要多轮对话
- [ ] 周统计正确（次数、总时长、高峰时段、Top 情境）
- [ ] 所有用户可见文案通过“无指责词”检查（词表：又、竟然、居然、拖延、懒、失败）
- [ ] 数据口径与 T21 手机使用时长一致（同一时段两侧数字可对上）

## 7. 风险与降级

- 坦白变成负担 → 允许“不想说细节”，只记录次数即可
- 统计口径混乱 → 在 02 文档里定义清楚“一次分心”的判定规则

## 8. 提示

> 这个功能的价值在措辞，不在算法。找 3 个同学读一遍文案，问他们“看完想不想再坦白一次”。
