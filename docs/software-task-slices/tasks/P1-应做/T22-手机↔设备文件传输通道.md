## 1. 目标

用户手机里拍的资料能进到设备里，不用连电脑、不用插 U 盘。

## 2. 需求依据

- **SR-19** — 支架：…… & 文件拍照传输（P42）

## 3. 输入 / 输出

**输入**

- T01 系统网络配置
- T10 inbox 目录约定

**输出（可交付物）**

- 设备热点与二维码入口
- 手机上传网页
- inbox 落盘与 T11 的对接

## 4. 工作内容

- [ ] 网络方案（推荐 A）：设备开热点 Flow-Flow（hostapd + dnsmasq），屏幕显示二维码指向 http://flow.local/upload
- [ ] 方案 B：手机与设备在同一局域网（教室 WiFi），用 mDNS 解析 flow.local
- [ ] 上传页：单页 Web（可复用前端工程），支持多选图片/PDF，单文件上限 20MB，显示进度与结果
- [ ] 落盘：/opt/flow/data/inbox/YYYYMMDD-HHMMSS-<uid>.<ext>，同时写 inbox.json 元数据
- [ ] 对接：文件落地后发 event inbox.file → T11 生成待确认草稿
- [ ] 安全：局域网内免密但只接受热点内设备；上传目录不可执行；文件名做白名单清洗
- [ ] 降级：网络不通时提示“用设备摄像头直接拍”，不要卡死在这里

## 6. 验收标准（Definition of Done）

- [ ] 手机连上热点后扫码打开上传页 ≤ 30 秒
- [ ] 一次上传 5 张图片全部成功并出现在待确认列表
- [ ] 超过大小限制的文件被友好拒绝而不是崩溃
- [ ] 设备重启后热点自动恢复
- [ ] 上传的文件不会进入系统可执行路径

## 7. 风险与降级

- Pi 热点与 STA 同时工作不稳定 → 只做 AP 模式，或要求设备网线接入
- iOS 对 http 明文有提示 → 页面做清楚引导，或后续加自签证书
- MTP/USB 直连在 Linux 上支持差 → 不作为主方案

## 8. 提示

> 二维码直接渲染在 14×14 屏上即可，不需要打印。记得把二维码做够大（≥ 300px）才能扫到。
