# T30 · 打包、烧录与出厂配置

| 前置依赖 | `T01`、`T28` |

## 1. 目标

从“我这台能用”变成“换一台也能 20 分钟搞定”——这是能不能交付的分水岭。

## 2. 需求依据

- **SR-19** — 设备是一个实体产品（15×15×5cm），软件必须可复制到多台设备。

## 3. 输入 / 输出

**输入**

- T01 镜像基线
- 全部代码

**输出（可交付物）**

- 出厂镜像或一键安装脚本
- 首次开机向导
- 升级与备份恢复工具

## 4. 工作内容

- [ ] 交付方式二选一：定制镜像（rpi-imager + firstrun 脚本）或 deb 包 + install.sh
- [ ] 首次开机向导：WiFi、创建用户、选音色、设作息，结果写 config.yaml
- [ ] 版本管理：version.json + 升级脚本，升级必须保留 db 与用户数据
- [ ] 备份恢复：flow backup / flow restore，恢复后功能等价
- [ ] 文档：安装手册、故障排查表、引脚与接线表、常见问题
- [ ] 出厂自检：烧录后自动跑一遍 hal.selftest 并打印报告

## 6. 验收标准（Definition of Done）

- [ ] 全新 SD 卡到设备可用 ≤ 20 分钟（含烧录）
- [ ] 升级过程不丢任何用户数据
- [ ] 备份恢复后功能与恢复前完全等价
- [ ] 安装手册可被一个没写过代码的同学照着完成
- [ ] 出厂自检报告能一眼看出哪个外设没接好

## 7. 风险与降级

- 镜像越大越难维护 → 只装必要依赖，定期清理缓存
- 升级失败变砖 → 保留上一版本目录，一键回滚

## 8. 提示

> 至少准备 2 张已经烧好的 SD 卡作为备份。演示前一天再验证一次能否从零装起。
