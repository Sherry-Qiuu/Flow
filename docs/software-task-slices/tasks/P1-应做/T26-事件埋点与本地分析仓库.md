## 1. 目标

产品要能自我证明有效：记录关键事件并算出可用指标——不然“减少焦虑”永远只是一句口号。

## 2. 需求依据

- **SR-16** — 刻画用户形象，鼓励用户持续减少分心（P35）
- **SR-01** — 效率工具最终是为了解决用户的情绪问题（P7）——需要用数据支撑这个主张。

## 3. 输入 / 输出

**输入**

- T03 事件总线
- T10 data 层

**输出（可交付物）**

- 事件规范与白名单
- device_events + metrics_daily 聚合
- GET /api/metrics 接口

## 4. 工作内容

- [ ] 事件规范：{event, user_id, ts, props}，白名单 schema，禁止随手埋点（新增事件要过代码评审）
- [ ] 关键事件：任务创建/完成、步骤完成/跳过/卡住、计划确认/重排、提醒触发与响应、手机契约准时率、坦白次数、休息接受率、连续使用天数
- [ ] 存储：device_events 明细 + metrics_daily 每日聚合（启动时增量计算）
- [ ] 指标口径：完成率、准时率、平均单步时长、分心次数/周、休息接受率、连续天数
- [ ] 本地优先：数据不出设备，只提供本地 REST 查询
- [ ] 隐私：可全局关闭采集；关闭后只保留系统日志，不写 device_events
- [ ] 容量：事件表按 90 天归档，避免无限增长
- [ ] 性能：埋点必须异步且不阻塞主链路（< 5ms 开销）

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

| 子任务 | 名称 | 产物 | 完成判据 | 人日 |
|---|---|---|---|---|
| `T26.1` | 事件规范与白名单 | `app/analytics/events.py` | 15 个事件常量；新增事件需评审；禁止随手埋点 | 0.5 |
| `T26.2` | 异步采集 | `app/analytics/collector.py` | 对主链路延迟影响 <5ms；关闭开关后不写任何事件 | 0.5 |
| `T26.3` | 每日聚合 | `app/analytics/rollup.py` | 启动增量计算 metrics_daily；7 日指标与手工核对一致 | 0.5 |
| `T26.4` | 查询接口与归档 | `GET /api/metrics?range=7d` | 完成率/准时率/平均单步/分心次数/休息接受率/连续天数；90 天归档 | 0.5 |

**小计 2.00 人日**

## 6. 接口契约

```
# 事件样例
{"event": "step.completed", "user_id": "u1", "ts": "...", "props": {"task_id": "t1", "planned_min": 30, "actual_min": 42}}
{"event": "reminder.responded", "props": {"id": "r9", "action": "ack|ignored", "latency_s": 12}}

# 查询
GET /api/metrics?range=7d
→ {"completion_rate": 0.68, "on_time_rate": 0.72, "avg_step_min": 28,
   "distractions_per_week": 6, "rest_accept_rate": 0.5, "streak_days": 4}
```

## 7. 实现要点

```
15 个事件（白名单，新增需评审）：

    task.created / task.completed / step.completed / step.skipped / step.stuck
    plan.confirmed / plan.revised
    reminder.fired / reminder.responded
    phone.session.started / phone.session.ended / phone.session.overdue
    distraction.logged / rest.accepted / app.opened

collector 异步队列写入，主链路只 append 一次（<5ms）
rollup 启动时增量算 metrics_daily；device_events 保留 90 天
```

## 8. 验收标准（Definition of Done）

- [ ] 埋点对主链路延迟影响 < 5ms（压测验证）
- [ ] 7 日指标与手工核对数据一致（抽查完成率与分心次数）
- [ ] 关闭采集后不再写入任何 device_event
- [ ] 事件表超过 90 天的数据被正确归档且不影响查询

## 9. 风险与降级

- 埋点名不一致导致指标全错 → 事件常量集中定义，禁止字符串硬编码
- 隐私争议 → 默认本地、默认可关闭、默认不采集内容仅采集行为

## 10. 提示

> 先定义 15 个事件就够用了。埋点越少越准，多了没人看。
