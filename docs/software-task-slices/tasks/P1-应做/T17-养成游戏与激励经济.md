## 1. 目标

把“完成任务”变成“养大一个小东西”，用陪伴感延长坚持周期，而不是用惩罚制造压力。

## 2. 需求依据

- **SR-09** — 在机器人上做养成游戏（P24）——治理拖延的手段，必须与任务完成强绑定。

## 3. 输入 / 输出

**输入**

- T16 reward_events
- T05 表情与动效
- T10 companion_state

**输出（可交付物）**

- 角色与成长阶段
- 积分规则
- 待机页表现与状态查看

## 4. 工作内容

- [ ] 主体：一只会随用户状态变化的角色，5 个成长阶段（视觉差异明显）
- [ ] 经济规则：完成一步 +1、完成整任务 +5、按时开始 +3、连续 3 天 +10；中断不扣分（产品原则：不制造惩罚焦虑）
- [ ] 状态：exp / level / streak / last_seen_at，用“陪伴”叙事而非“喂养”叙事
- [ ] 表现：待机页角色在主位；完成任务时角色开心；用户焦虑或连续工作过久时角色安静陪伴（不催）
- [ ] 轻目标：每日完成“三个小步”即达成，不设失败态、不设计离线惩罚
- [ ] 多用户隔离：每个用户独立的角色与等级
- [ ] 可解释：设置里能查看当前等级与距离下一级的进度

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

**小计 2.00 人日**

## 7. 实现要点

```
经济规则（写在 app/emotion/rewards.py 一处，不要散落）：

    完成一步        +1
    完成整任务      +5
    按时开始        +3
    连续 3 天       +10
    中断/断更        0   ← 永不扣分

等级：level = f(exp)，5 个阶段，视觉差异明显
叙事：用“陪伴”不用“喂养”；焦虑时角色安静，不催
```

## 8. 验收标准（Definition of Done）

- [ ] 完成任务后经验/等级正确变化并有可见动效
- [ ] 断更 3 天不会出现“死亡 / 清零 / 降级”
- [ ] 多用户各自独立，互不串级
- [ ] 角色状态与用户当前情绪/负荷大致一致（人工抽查）
- [ ] 所有数值规则可在设置页查看，不是黑盒

## 9. 风险与降级

- 养成系统喧宾夺主 → 待机页可关闭角色，专注执行时绝不出现
- 激励失衡导致刷任务 → 每步积分设上限，重复任务递减

## 10. 提示

> 这一块最容易过度设计。先做“成长 + 一句陪伴”，不要做商店、道具、货币循环。
