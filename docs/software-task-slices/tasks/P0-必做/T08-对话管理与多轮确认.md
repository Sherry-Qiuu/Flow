# T08 · 对话管理与多轮确认

> 工作流：**单通道交互**（CHN）・优先级 **P0**・规模 **M**（2 人日）

| 字段 | 内容 |
|---|---|
| 任务 ID | `T08` |
| 工作流 | 单通道交互（`CHN`） |
| 优先级 | P0 |
| 规模 | M / 2 人日 |
| 前置依赖 | `T04`、`T06` |
| 需协同 | `T11`、`T12`、`T13` |
| 建议角色 | AI / 后端 |

## 1. 目标

让“商量”这件事真的成立：机器人能追问、能确认、能记住上下文，而不是各说各话。

## 2. 需求依据

- **SR-04** — 与用户进行商讨后指定最终版计划表（P19）
- **SR-06** — 拍照识别导入后，最后与用户进行确认（P20）

## 3. 输入 / 输出

**输入**

- T04 意图路由
- T06 final 文本
- T12 规划引擎接口

**输出（可交付物）**

- Dialogue 回合管理器
- Action 类型枚举与执行器
- 澄清 / 确认 / 超时 / 改口 四类策略

## 4. 工作内容

- [ ] 上下文：最近 8 轮对话 + 当前通道 + 当前计划草稿 + 当前用户
- [ ] 意图识别：LLM function calling，工具集固定为：切通道 / 增任务 / 改任务 / 删任务 / 生成计划 / 改计划 / 确认 / 取消 / 查询
- [ ] 澄清策略：缺槽位时一次只问一个问题（时长？哪天？哪个任务？），禁止连环追问
- [ ] 确认协议：删除、覆盖计划、清空数据等破坏性操作必须二次确认
- [ ] 改口处理：用户中途改主意时以最后一次为准，旧草稿作废但可撤销
- [ ] 超时：30 秒无响应回待机，草稿保留在会话里
- [ ] 输出：统一返回 Action 列表，由执行器分发到各模块，对话层不直接写库

## 5. 接口契约

```
class Action:  # 判别联合
    kind: "enter_channel|create_task|update_task|delete_task|build_plan|
           modify_plan|confirm|cancel|answer|ask"

Dialogue.turn(text: str, source: str) -> list[Action]
```

## 6. 验收标准（Definition of Done）

- [ ] “明天要交的物理实验报告” → 追问截止时间 → 生成任务草稿
- [ ] “不对，改成后天” → 正确修订已有草稿，而不是重建一条
- [ ] “删掉第二个任务” → 二次确认后才删除
- [ ] 30 秒无交互自动回到待机，再次唤醒上下文仍在
- [ ] 一句话包含两个意图（“打开计时器然后提醒我喝水”）能拆成两个 Action

## 7. 风险与降级

- LLM 输出格式不稳定 → 强制 JSON schema + 解析失败重试 1 次 + 规则兜底
- 上下文过长导致延迟 → 只保留关键槽位摘要，不塞全量历史

## 8. 提示

> 工具集定了就别随手加。每加一个工具，LLM 的路由准确率都会下降一点。
