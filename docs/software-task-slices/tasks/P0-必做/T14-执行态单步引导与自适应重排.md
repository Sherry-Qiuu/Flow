# T14 · 执行态单步引导与自适应重排

> 工作流：**任务与规划**（TASK）・优先级 **P0**・规模 **L**（3.5 人日）

## 1. 目标

执行时屏幕上只出现“下一步”，并且计划会跟着现实走——这是单通道体验的高潮段落。

## 2. 需求依据

- **SR-05** — 开始执行计划的时候屏幕上极简显示步骤（P19）
- **SR-08** — 用户通过任务规划后，机器人会定时提醒，并在任务完成过程中应变调整规划（P23）

## 3. 输入 / 输出

**输入**

- T13 已确认计划
- T15 提醒调度
- T04 通道机制

**输出（可交付物）**

- Executing 页面与专注计时
- 完成 / 跳过 / 卡住 三指令处理
- 局部重排算法与中断恢复

## 4. 工作内容

- [ ] 单步卡：任务名 + 当前步骤 + 剩余时间 + 三个语音指令（完成 / 跳过 / 卡住）
- [ ] 专注计时：默认 45 分钟工作 + 10 分钟休息，可语音修改；剩余 5 分钟播报一次
- [ ] 卡住处理：连续两次“卡住” → 自动把该步再拆细或降级为“只做 5 分钟版本”
- [ ] 完成：打勾 → 触发 T16 庆祝 → 自动进入下一步（是否需确认可配置）
- [ ] 超时：本步超出预估 30% → 询问“要不要延长 10 分钟 / 跳过 / 换个简单的先做”
- [ ] 局部重排：任务延误/新增/取消时只调整后续未开始项，已确认和已完成部分不动
- [ ] 中断恢复：断电、关屏、切用户回来后仍在同一步，计时按实际经过时间校正
- [ ] 节奏：连续完成 3 步给一次正向播报，避免每步都刷屏

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

| 子任务 | 名称 | 产物 | 完成判据 | 人日 |
|---|---|---|---|---|
| `T14.1` | 单步卡与专注计时 | `app/focus/session.py + ui Executing` | 屏上只有一个步骤 + 剩余时间；默认 45+10，可语音改 | 0.75 |
| `T14.2` | 完成 / 跳过 / 卡住 | `app/focus/commands.py` | 说“完成了” 1 秒内切下一步；连续两次卡住自动再拆细 | 0.75 |
| `T14.3` | 超时与延长 | `app/focus/overtime.py` | 超预估 30% 主动询问 延长/跳过/换简单任务 | 0.5 |

**小计 3.50 人日**

## 6. 接口契约

```
# 事件：focus.state {task_id, subtask_id, remaining_ms, elapsed_ms, status}
#       plan.item.advanced {from_id, to_id}
# REST：POST /api/focus/control {"action": "start|pause|skip|finish|extend", "minutes": 10}
#       POST /api/plan/replan {"reason": "delay|new_task|cancel"}
```

## 7. 实现要点

```
FocusSession 状态机：

    planned ──start──> running ──finish──> done
                 │        ├──pause──> paused
                 │        ├──skip───> skipped
                 │        └──stuck──> split(再拆细) → running
                 └──overrun(>1.3x)──> ask_extend

重排规则（replan.py）：
    只遍历 status in (planned, running) 且 start_at > now 的项
    已完成 / 已确认的项原地不动
    每次重排保存前值，支持一次撤销
```

## 8. 验收标准（Definition of Done）

- [ ] 执行时屏幕上只有一个步骤 + 剩余时间，没有任何任务列表
- [ ] 说“完成了”后 1 秒内切到下一步并播报
- [ ] 延误 20 分钟后自动给出重排建议，且不影响已完成项
- [ ] 重启设备后恢复到同一个步骤，计时误差 < 10 秒
- [ ] 连续两次“卡住”后该步骤被二次拆细

## 9. 风险与降级

- 频繁重排会让用户失去掌控感 → 重排必须可撤销，且每次只调整最小范围
- 计时与系统休眠不一致 → 用单调时钟 + 落库时间戳双向校正
