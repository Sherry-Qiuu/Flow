## 1. 目标

保证同一时刻屏幕上只有一个通道，并让用户一句话就能把想要的工具召唤出来——这是整个产品的核心机制。

## 2. 需求依据

- **SR-01** — 内置常见效率工具（钟、任务清单、计划表、专注计时器、提醒、可选音乐），对其进行单通道管理（P13）
- **SR-02** — 用户通过语音表达主动抓取工具的意愿，机器人直接提供工具（P14）
- **SR-01** — 单通道强制聚焦，降低过载（P16）

## 3. 输入 / 输出

**输入**

- T02 HAL（屏幕、传感器）
- T03 事件总线与 WS 协议
- 各通道的最小可用实现

**输出（可交付物）**

- Channel 抽象与通道注册表
- 状态机（IDLE / CHANNEL_ACTIVE）与返回栈
- 意图 → 工具路由
- GET /api/channel/current 与 POST /api/intent

## 4. 工作内容

- [ ] Channel 抽象：key / title / enter(ctx) / exit() / handle(intent) / tick(now) / snapshot()
- [ ] 内置六个通道：clock（钟）、tasks（任务清单）、plan（计划表）、focus（专注计时器）、reminder（提醒）、music（音乐）
- [ ] 状态机：任何时刻只能有一个 active 通道；切换必须先 exit 再 enter，禁止并存
- [ ] 返回栈：从 tasks 打开 task detail 后能回上一层，栈深限制 3 层防迷失
- [ ] 意图路由：解析 {intent: open_tool, tool, args}，歧义时只反问一句“你是想专注计时还是看任务清单？”
- [ ] 通道快照统一结构 {channel, data, hints} 交给 T05 渲染，前端不需要知道业务细节
- [ ] 异常兜底：通道 handler 抛异常 → 记录日志 → 自动退回 IDLE 并播报一句“刚才出了点问题，我们回到主页”
- [ ] 防过载：30 分钟内通道切换超过阈值（默认 12 次）→ 收敛到单通道并温和提示

## 6. 接口契约

```
class Channel(Protocol):
    key: str
    title: str
    def enter(self, ctx: Context) -> dict: ...   # 返回首帧 snapshot
    def exit(self) -> None: ...
    def handle(self, intent: Intent) -> list[Action]: ...
    def tick(self, now: datetime) -> list[Action]: ...
    def snapshot(self) -> dict: ...

# 事件：channel.enter / channel.exit / ui.phase
# REST：GET /api/channel/current → {channel, data, hints}
#       POST /api/intent {text, source} → {actions: [...]}
```

## 7. 实现要点

```
class Channel(Protocol):
    key: str
    title: str
    def enter(self, ctx) -> dict: ...   # 返回首帧 snapshot
    def exit(self) -> None: ...
    def handle(self, intent) -> list[Action]: ...
    def tick(self, now) -> list[Action]: ...
    def snapshot(self) -> dict: ...

Machine.activate(key, args):
    if self.current: self.current.exit()      # 必须先退出
    self.current = registry[key]
    snap = self.current.enter(ctx)
    bus.publish("channel.enter", {"channel": key})
    bus.publish("ui.phase", {"phase": "idle", "channel": key})
    return snap

tick 统一 1Hz，其余全部事件驱动，避免树莓派上 CPU 打满。
```

## 8. 验收标准（Definition of Done）

- [ ] 任意时刻调用 GET /api/channel/current 只返回一个通道，压测 1000 次无并发异常
- [ ] 说“打开专注计时器”，1 秒内屏幕切到 focus 通道且原通道正确退出
- [ ] 在 plan 通道说“看下任务清单”，干净切换，屏幕上无上一个通道的残留元素
- [ ] 通道 handler 人为抛异常时自动回退 IDLE，服务不崩溃
- [ ] 切换 12 次后触发过载提示（阈值可配置）

## 9. 风险与降级

- 前端若自行维护通道状态，会与后端状态不一致 → 前端只做渲染，通道状态单一可信源在后端
- tick 频率过高导致 CPU 占用 → 统一 1Hz 主循环，其余按事件驱动

## 10. 提示

> 单通道不是“只做一件事”，而是“只显示一件事”。后端可以同时算计划，但屏幕上只允许一个焦点。
