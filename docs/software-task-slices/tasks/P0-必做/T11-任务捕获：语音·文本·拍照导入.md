# T11 · 任务捕获：语音 / 文本 / 拍照导入

> 工作流：**任务与规划**（TASK）・优先级 **P0**・规模 **L**（3.5 人日）

| 字段 | 内容 |
|---|---|
| 任务 ID | `T11` |
| 工作流 | 任务与规划（`TASK`） |
| 优先级 | P0 |
| 规模 | L / 3.5 人日 |
| 前置依赖 | `T02`、`T06`、`T10` |
| 需协同 | `T08`、`T12`、`T13`、`T22` |

## 1. 目标

让用户用最省力的方式把“一堆模糊的事”灌进系统——说一句、拍一张，就变成结构化待办。

## 2. 需求依据

- **SR-03** — 用户通过输入杂乱的任务……将任务告诉机器人（P19）
- **SR-06** — 机器人有摄像头传感器，用户拍照需要做的课程任务，通过照片自动识别并导入到待办事项，最后与用户进行确认（P20）

## 3. 输入 / 输出

**输入**

- T06 语音 final 文本
- T02 Camera 接口
- T10 DAO

**输出（可交付物）**

- TaskDraft 抽取器（文本 / 语音）
- 拍照 → 预览 → 识别 → 确认 全流程
- 离线排队与去重

## 4. 工作内容

- [ ] 文本/语音抽取：一句话可含多条任务，用 LLM 或规则抽成 TaskDraft[]（title / deadline / est_minutes / course / priority / 原文引用）
- [ ] 拍照流程：取景预览 → 亮度与对焦检测 → 拍摄 → 屏幕显示缩略图请用户确认 → 识别
- [ ] 识别引擎：优先云端 VLM（Qwen-VL / 豆包），失败降级本地 PaddleOCR + 规则解析
- [ ] 解析目标：课程任务清单、作业照片、黑板板书；至少抽出标题与截止时间
- [ ] 确认页：逐条勾选/编辑/删除，确认后批量写入 DB；取消则无残留
- [ ] 离线队列：无网时原图存 inbox/，恢复网络后按队列批量识别并提示
- [ ] 去重：标题 + 截止时间相似度 > 0.9 → 提示“这条似乎已经加过了，还要再加吗”
- [ ] 来源标记：source ∈ {voice, photo, phone, text, manual}，供后续统计使用

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

| 子任务 | 名称 | 产物 | 完成判据 | 人日 |
|---|---|---|---|---|
| `T11.1` | TaskDraft 抽取器 | `app/capture/extract.py` | 一句话含 3 条任务正确拆成 3 个草稿；字段含 deadline/est/course | 0.75 |
| `T11.2` | 拍照流程与质量检测 | `app/capture/photo.py` | 预览→亮度/对焦检测→拍摄→缩略图确认→失败可重拍 | 0.75 |
| `T11.3` | 云端 VLM 识别 | `app/capture/vlm.py` | JSON schema 约束；标题与截止时间准确率 ≥80%（20 张真实照片） | 1.0 |
| `T11.4` | 本地 OCR 降级 | `app/capture/ocr.py` | PaddleOCR + 规则解析，断网也能出草稿 | 0.5 |
| `T11.5` | 确认页与去重 | `app/capture/commit.py + ui CaptureReview` | 勾选/编辑/批量入库；相似度 >0.9 提示已存在；取消无残留 | 0.5 |

**小计 3.50 人日**

## 6. 接口契约

```
class TaskDraft:  # 未入库的草稿
    title: str
    deadline: datetime | None
    est_minutes: int | None
    course: str | None
    priority: str          # low | normal | high
    source: str
    quote: str             # 原文片段，便于用户核对

def extract_from_text(text: str) -> list[TaskDraft]
def extract_from_image(jpeg: bytes) -> list[TaskDraft]
def commit(drafts: list[TaskDraft], user_id: str) -> list[Task]
```

## 7. 实现要点

```
拍照导入链：

    frame  = hal.camera.capture()          # 不可用返回 None
    ok     = photo.check_quality(frame)    # 亮度/模糊/占比
    drafts = vlm.extract(frame) or ocr.extract(frame)
    final  = ui.confirm(drafts)            # 勾选/编辑
    tasks  = repo.tasks.bulk_create(final)

离线：原图存 data/inbox/，恢复网络后批量补识别
去重：标题 + 截止时间相似度 > 0.9 提示“似乎已经加过了”
```

## 8. 验收标准（Definition of Done）

- [ ] 一句话包含 3 个任务时，正确拆成 3 条草稿且不遗漏
- [ ] 拍照识别课程作业，标题与截止时间字段准确率 ≥ 80%（用 20 张真实照片测）
- [ ] 用户取消确认后，数据库无任何残留记录
- [ ] 断网状态下拍照不阻塞界面，恢复网络后自动补识别
- [ ] 重复任务被识别并提示，不静默重复入库

## 9. 风险与降级

- 手写体与反光照片识别率低 → 拍照环节就做质量检测并要求重拍，别指望模型硬扛
- VLM 输出不稳定 → 用 JSON schema 约束 + 失败重试 + 人工确认页兜底

## 10. 提示

> 拍照识别是整个项目最出彩的演示点。准备 10 张“设计过的”课程单作为演示素材，通过率会高很多。
