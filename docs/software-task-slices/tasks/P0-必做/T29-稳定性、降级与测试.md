## 1. 目标

现场演示不翻车的前提：所有异常路径都想过、都试过。

## 2. 需求依据

- **SR-01** — 开机即用、断网可用是嵌入式产品的基本盘。

## 3. 输入 / 输出

**输入**

- 全部模块
- T28 主链路

**输出（可交付物）**

- 降级矩阵
- 核心逻辑单测 + mock 集成测试
- soak 测试报告

## 4. 工作内容

- [ ] 崩溃恢复：systemd 拉起 + 断点续跑（当前步骤、计时、提醒队列从 DB 恢复）
- [ ] 降级矩阵：无网 → 本地 ASR/TTS + 规则规划；无摄像头 → 只收语音；无麦克风 → 屏幕 + 手势；无传感器 → 手动模式
- [ ] 压力：连续 12 小时运行，内存与文件句柄不增长；1000 条任务列表不卡
- [ ] 测试：规划校验器、重排算法、提醒时间计算、计时恢复四大核心逻辑必须单测覆盖
- [ ] HAL 用 mock 跑集成测试，CI 一键执行
- [ ] 错误提示：用户看到“我没听清，再说一次”，而不是任何英文堆栈
- [ ] 日志：flow-diag 一键导出诊断包，包含日志、配置、版本、传感器状态

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

| 子任务 | 名称 | 产物 | 完成判据 | 人日 |

**小计 2.00 人日**

## 7. 实现要点

```
降级矩阵（app/degrade.py）：

    无网络      → asr_local + tts cache + RuleEngine
    无摄像头    → 只收语音输入，拍照入口隐藏
    无麦克风    → 屏幕 + 手势 + 按钮
    无传感器    → 手机在位改手动“我拿/我放”

故障注入清单：拔网线、unplug 摄像头、kill -9 backend、写坏 db
每种都要在 30 秒内自恢复并继续工作。
```

## 8. 验收标准（Definition of Done）

- [ ] 拔网 / 拔摄像头 / kill -9 服务 三种故障下，系统都能自恢复并继续工作
- [ ] 核心引擎单测覆盖率 ≥ 70%，CI 可一键运行
- [ ] 12 小时 soak 测试无内存泄漏（内存增长 < 50MB）
- [ ] 用户可见界面不出现任何英文异常信息
- [ ] 诊断包能独立复现问题（拿给另一人也能看懂）

## 9. 风险与降级

- 只测 happy path → 专门安排一次“破坏性测试”会议，所有人轮流搞破坏

## 10. 提示

> 写一张“故障注入 checklist”，演示前一周每天抽 3 条随机试。这是最有效的保险。
