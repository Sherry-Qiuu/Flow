## 1. 目标

把 30 个模块拧成一条 5 分钟能讲完的演示线，并且现场一定不翻车。

## 2. 需求依据

- **SR-01** — 整个产品文档的功能需要被完整演示一次才能证明成立。

## 3. 输入 / 输出

**输入**

- 各模块可运行版本
- T30 的可复现部署

**输出（可交付物）**

- 主链路 e2e 测试用例
- 演示分镜脚本（含兜底话术）
- 一键重置与剧本模式

## 4. 工作内容

- [ ] 主链路串起来：开机自检 → 待机 → 语音“我要整理明天的任务” → 拍照/语音灌任务 → 生成计划 → 协商确认 → 执行单步 → 完成庆祝 → 拿手机用 10 分钟 → 到点提醒 → 归还 → 养成成长 → 周报
- [ ] 分镜脚本：时间点 / 说什么 / 屏幕应出现什么 / 设备应说什么 / 失败时怎么接
- [ ] 兜底一：flow demo reset 一键恢复预置演示数据（< 10 秒）
- [ ] 兜底二：剧本模式——LLM 或网络不可用时使用预生成响应，仍能完整演完
- [ ] 兜底三：关键节点人工触发（按键/命令行），避免语音识别失败卡死
- [ ] 联调清单：按 02 架构文档的接口表逐条核对，勾选完成
- [ ] 三次全流程彩排，记录每次卡点并修复

## 5. 子任务拆解

每项 ≤0.5 人日，可单独勾选验收。做完一项就在 `产物` 那一列把文件建出来。

| 子任务 | 名称 | 产物 | 完成判据 | 人日 |
|---|---|---|---|---|
| `T28.1` | 主链路 e2e 用例 | `tests/e2e/test_main_flow.py` | 自检→灌任务→生成计划→确认→执行→庆祝→手机契约→周报全通 | 0.5 |
| `T28.2` | 分镜脚本与兜底话术 | `docs/demo/storyboard.md` | 每个环节有时间点/台词/屏幕预期/失败兜底 | 0.5 |
| `T28.3` | 一键重置与剧本模式 | `scripts/flow-reset + app/demo/scripted.py` | 重置 <10 秒；断网也能完整演完 | 0.5 |
| `T28.4` | 三次彩排与修复 | `docs/demo/rehearsal-log.md` | 连续 3 次无卡死、无白屏、无崩溃 | 0.5 |

**小计 2.00 人日**

## 7. 实现要点

```
主链路 e2e（tests/e2e/test_main_flow.py）：

    selftest → 语音灌 3 条任务 → decompose → plan → confirm
    → execute 首步 → finish → celebrate → 拿手机 10 分钟
    → 到点提醒 → 归还 → 周报

兜底三件套：
    scripts/flow-reset     一键恢复演示数据（<10s）
    app/demo/scripted.py   LLM/网络不可用时用预生成响应
    命令行触发            语音失败时手动推进（不卡死）
```

## 8. 验收标准（Definition of Done）

- [ ] 连续 3 次完整彩排无卡死、无白屏、无服务崩溃
- [ ] 断网状态下可完成 80% 以上演示流程
- [ ] 一键重置在 10 秒内完成，重置后状态与首次开机一致
- [ ] 分镜脚本每个环节都有兜底话术，无“这里如果失败就跳过”的空洞

## 9. 风险与降级

- 最后一刻还在改代码 → 演示前 3 天冻结功能，只修 bug
- 设备电量/温度问题 → 演示时全程接电源

## 10. 提示

> 演示的价值不在功能多，而在于“这条线从头到尾没断”。宁可少讲两个功能，也不要中途卡住。
