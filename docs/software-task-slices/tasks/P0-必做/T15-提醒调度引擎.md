## 1. 目标

一个可靠、断电不丢、一定会响的提醒系统——所有“到点提醒”都归它管。

## 2. 需求依据

- **SR-10** — 用户通过内置应用设定 daily 提醒（P29）
- **SR-12** — 用户要求每天早上起床时分播报天气预报（P30）
- **SR-13** — 在拿取手机做任何事情之前设定手机使用时长，到达设定时间之后提醒手机归位（P31–P32）
- **SR-14** — 外出运动 / 做更丰富的休息的时候提醒（P33）

## 3. 输入 / 输出

**输入**

- T10 数据层
- 天气 API（可选）

**输出（可交付物）**

- 统一提醒模型与调度器
- 语音创建/修改/关闭提醒
- 错过的补偿策略与静默规则

## 4. 工作内容

- [ ] 提醒类型：一次性（at）、每日（daily）、每周（weekly）、间隔（every）、情境事件（event）
- [ ] 调度：APScheduler（SQLAlchemy jobstore）或自写 asyncio 主循环，任务持久化到 DB，重启自动恢复
- [ ] 错过补偿：设备关机期间错过的提醒，开机后按策略处理（错过 > 2 小时合并成一条摘要）
- [ ] 去重与静默：同一提醒不重复响；夜间静音默认 22:00–07:00（手机归位提醒可例外）
- [ ] 播报内容：模板 + 变量（天气、任务名、剩余时间）；天气走和风/心知 API，失败则省略该句
- [ ] 触发链路：reminder.fired → T07 播报 + T05 显示 → 记录响应（按时/忽略）
- [ ] 语音管理：“每天 7 点提醒我背单词” → 创建；“关掉那个提醒” → 列出候选后确认
- [ ] 时区：全部按 Asia/Shanghai 计算，跨天与闰日单独测试

## 6. 接口契约

```
# 事件：reminder.fired {id, title, kind, payload}
# 模型：Reminder(id, user_id, kind, spec_json, next_fire_at, enabled, last_fired_at)
# spec 示例：{"type": "daily", "at": "07:00", "template": "早上好，今天{brief}，{weather}"}
#           {"type": "at", "at": "2026-11-08T19:30:00+08:00", "template": "该开始写论文了"}
#           {"type": "every", "minutes": 45, "template": "站起来走两步"}

def schedule(reminder: Reminder) -> None
def list_upcoming(user_id: str, hours: int = 24) -> list[Reminder]
```

## 7. 实现要点

```
Reminder(id, user_id, kind, spec_json, next_fire_at, enabled, last_fired_at)

spec 示例：
    {"type":"daily","at":"07:00","template":"早上好，今天{brief}，{weather}"}
    {"type":"at","at":"2026-11-08T19:30:00+08:00","template":"该开始写论文了"}
    {"type":"every","minutes":45,"template":"站起来走两步"}
    {"type":"event","on":"phone.removed","template":"记得 10 分钟内放回来"}

补偿：启动时扫 next_fire_at < now 的记录，错过 >2h 合并成一条摘要后再排下一次
```

## 8. 验收标准（Definition of Done）

- [ ] 设置 2 分钟后的提醒，实际误差 ≤ 3 秒
- [ ] 断电 1 小时后重启，未触发的提醒被正确补偿且不重复
- [ ] 每日重复跨天正确，连续 7 天无重复、无漏触发
- [ ] 时区与跨月跨年边界测试通过
- [ ] 1000 条提醒存量下调度延迟无明显退化
- [ ] 夜间静音生效，但“手机归位”类提醒仍可提示

## 9. 风险与降级

- 树莓派时钟不准导致提醒漂移 → chrony 校时 + 启动时校核
- APScheduler 与 asyncio 阻塞 → 调度回调里不要做重活，只发事件
