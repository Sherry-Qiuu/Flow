## 1. 目标

一张稳定的本地数据底座：所有模块都通过 DAO 读写，断电不丢，换人不串。

## 2. 需求依据

- **SR-21** — 多用户与数据持久化为用户追加需求，但所有功能都依赖它。

## 3. 输入 / 输出

**输入**

- T03 服务骨架

**输出（可交付物）**

- SQLite schema + 迁移机制
- 各域 DAO / Repository
- 每日自动备份与恢复命令

## 4. 工作内容

- [ ] SQLite（WAL 模式）+ SQLModel（或 SQLAlchemy 2.0），数据库文件 /opt/flow/data/flow.db
- [ ] 表：users, tasks, subtasks, plans, plan_items, focus_sessions, reminders, phone_sessions, distractions, reward_events, companion_state, device_events, metrics_daily, settings, device_status
- [ ] 迁移：schema_version 表 + 顺序迁移脚本（或 alembic），启动时自动升级并备份旧库
- [ ] DAO：每域一个 Repository，业务层禁止裸 SQL；所有查询强制带 user_id
- [ ] 时间：库内统一 UTC ISO8601，展示层转 Asia/Shanghai
- [ ] 备份：每日 03:00 复制到 backup/，保留 7 份；flow restore 命令一键回滚
- [ ] 索引：tasks(user_id,status)、plan_items(plan_id,order_index)、reminders(next_fire_at)、device_events(ts)
- [ ] 软删除：tasks 用 deleted_at，避免家长/误删场景下数据永久丢失

## 5. 接口契约

```
# 核心实体（简化）
User(id, name, nickname, created_at, settings_json)
Task(id, user_id, title, note, source, status, est_minutes, due_at, priority, deleted_at)
SubTask(id, task_id, title, est_minutes, order_index, done_at)
Plan(id, user_id, plan_date, status, version, created_at)
PlanItem(id, plan_id, task_id, subtask_id, start_at, end_at, order_index, status)
Reminder(id, user_id, kind, spec_json, next_fire_at, enabled, last_fired_at)
FocusSession(id, user_id, plan_item_id, started_at, ended_at, interruptions_json)
PhoneSession(id, user_id, purpose, planned_minutes, started_at, ended_at, returned_on_time)
```

## 6. 验收标准（Definition of Done）

- [ ] 空库初始化一键完成，重复执行幂等
- [ ] 进程 kill -9 后重启，WAL 恢复且已提交数据不丢
- [ ] 备份 → 破坏数据 → restore 演练成功，数据完全一致
- [ ] 所有 DAO 的单测覆盖：以用户 A 身份读不到用户 B 的数据
- [ ] 库文件损坏时给出明确错误并自动使用最近备份

## 7. 风险与降级

- schema 频繁变更拖慢并行开发 → 第二周冻结 P0 表结构，后续只加表不改字段
- SD 卡写入寿命 → 减少高频写（focus tick 不落库，只在状态变化时写）
