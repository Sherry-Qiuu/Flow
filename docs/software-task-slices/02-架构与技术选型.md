# 02 · 系统架构与技术选型

## 整体架构

```
┌──────────────────────────────────────────────────────────────────┐
│ 【屏幕侧】14x14cm，触屏，Chromium Kiosk 全屏                     │
│ React Web UI (T05)：七个页面，触屏 + 语音操作                    │
└──────────────────────────────────────────────────────────────────┘
                              │  WebSocket · JSON 事件（state.sync / ui.phase / assistant.say）
┌──────────────────────────────────────────────────────────────────┐
│ 【FastAPI 本地服务 127.0.0.1:8000】(T03)                         │
│                                                                  │
│ 单通道状态机 T04 · 对话管理 T08 · 拆解规划引擎 T12               │
│ 提醒调度 T15 · 情绪与激励 T16–19 · 手机使用契约 T21              │
│ 任务捕获 T11 · 语音管线 T06/T07 · SQLite + DAO T10               │
│ 账号与多用户 T24/T25 · 事件埋点 T26 · 周报 T27                   │
└──────────────────────────────────────────────────────────────────┘
                              │  Python 接口（probe / capture / state / set_volume）
┌──────────────────────────────────────────────────────────────────┐
│ 【HAL 硬件抽象层】(T02)：含 mock 实现，无外设也能开发            │
└──────────────────────────────────────────────────────────────────┘
  屏幕(HDMI/DSI) · 摄像头 CSI/USB · 麦克风 USB · 扬声器 · ToF VL53L0X · 微动开关 · INA219

外部依赖（全部可降级）：LLM API · 云端 ASR · 云端 TTS · 云端 VLM · 天气 API
```

**分层原则**：UI 只管画，后端只管算，HAL 只管读硬件。三层之间只通过 **WebSocket 事件**（UI↔后端）和 **Python 接口**（后端↔HAL）通信，不允许跨层直连。

## 技术选型

| 层 | 选型 | 为什么 |
|---|---|---|
| 操作系统 | Raspberry Pi OS Lite 64-bit (Bookworm) | 无桌面环境，减少故障面 |
| 后端框架 | Python 3.11 + FastAPI + uvicorn（单 worker） | 异步友好、WebSocket 原生支持 |
| 实时通道 | WebSocket + JSON 消息协议 | 屏幕需要毫秒级状态同步 |
| 前端 | React 18 + Vite + TypeScript + TailwindCSS + Framer Motion | 开发快、动效强、可在电脑上开发 |
| 显示 | Chromium kiosk 全屏 | 避免自绘 UI 框架，复用 Web 生态 |
| 数据库 | SQLite (WAL) + SQLModel | 单文件、零运维、断电可恢复 |
| 调度 | APScheduler（SQLAlchemy jobstore） | 任务持久化，重启可恢复 |
| LLM | DeepSeek / Qwen（OpenAI 兼容接口） | 结构化输出 + function calling |
| ASR | 云端流式识别（主）+ Vosk 中文小模型（降级） | 准确率与离线可用性兼顾 |
| TTS | edge-tts（主）+ piper（降级）+ 预生成缓存 | 音色自然、免费、可离线 |
| VAD | silero-vad | 比 webrtcvad 更稳，CPU 占用可接受 |
| 视觉 | picamera2 / OpenCV + 云端 VLM（Qwen-VL）+ PaddleOCR 降级 | 拍照导入课程任务 |
| 传感器 | gpiozero + lgpio / INA219 | 手机在位、充电、触屏输入 |
| 手机传输 | hostapd 热点 + 二维码上传页 | 不依赖外网，不装 App |
| 部署 | systemd + 定制镜像 + flow 运维命令 | 开机即用、可复制 |

> 选型不是不可改。但**第二周之后不要再换**——换一次框架等于让三个人的工作同时停摆。

## 接口约定（所有人必须遵守）

1. **单一可信源** — 通道状态、当前计划、计时只由后端持有，前端永远只做渲染。
2. **事件命名** — `域.对象.动作`，如 `task.created`、`plan.confirmed`、`phone.changed`。常量集中在 topics.py。
3. **消息格式** — `{type, payload, seq, ts}`，Pydantic 校验；未知 type 只记日志不抛错。
4. **时间格式** — 库内 UTC ISO8601；对用户展示一律 Asia/Shanghai；所有时间计算用带时区对象。
5. **错误处理** — 模块内部抛异常可以，跨模块边界必须转成 `error` 事件或降级返回值，不允许让整条链路崩掉。
6. **命名规范** — Python: snake_case；TS: camelCase；数据库表: 复数 snake_case；事件: 小写点分。
7. **无硬编码** — 阈值、文案、提示语全部进 config.yaml 或文案表，方便现场调参。
8. **可关可降级** — 每个 P1/P2 功能都必须有“关掉之后主链路照常跑”的实现路径。

## 消息协议

### 服务端 → 客户端

```jsonc
{"type":"state.sync","payload":{...},"seq":1,"ts":"..."}            // 连接即全量同步
{"type":"ui.phase","payload":{"phase":"idle|listening|thinking|plan_review|executing|celebrating|resting",
                                  "channel":"clock|tasks|plan|focus|reminder|music"}}
{"type":"speech.partial","payload":{"text":"..."}}                     // 实时识别中间结果
{"type":"speech.final","payload":{"text":"..."}}                       // 断句后的最终文本
{"type":"assistant.say","payload":{"text":"...","emotion":"happy"}}   // 语音+表情同步
{"type":"task.created","payload":{"tasks":[...]}}
{"type":"plan.draft","payload":{"plan_id":"...","items":[...]}}
{"type":"plan.confirmed","payload":{"plan_id":"..."}}
{"type":"focus.state","payload":{"task_id":"...","remaining_ms":1234}}
{"type":"reminder.fired","payload":{"id":"...","title":"...","kind":"timer"}}
{"type":"phone.changed","payload":{"present":true,"charging":false}}
{"type":"reward.event","payload":{"kind":"step_done","points":5}}
{"type":"error","payload":{"code":"...","message":"..."}}
```

### 客户端 → 服务端

```jsonc
{"type":"user.intent","payload":{"text":"...","source":"voice|touch|ui"}}
{"type":"ui.action","payload":{"action":"plan.confirm","plan_id":"..."}}
{"type":"focus.control","payload":{"action":"start|pause|skip|finish"}}
{"type":"user.auth","payload":{"user_id":"u_02"}}                       // 多用户切换
```

## 关键设计决策（ADR）

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| UI 技术 | Web + Chromium kiosk，而非 Qt 自绘 | 开发速度快一个数量级，可在电脑上调试 | 内存占用高约 300MB |
| 通道状态归属 | 后端单一可信源 | 避免前后端状态错位 | 每次切换多一次往返 |
| 拆解引擎降级 | 规则引擎兜底 | LLM 不可用时产品仍成立 | 需要维护两套实现 |
| 语音唤醒 | MVP 用按键/VAD，后加唤醒词 | 误唤醒是体验杀手，先不背这个风险 | 演示少一个亮点 |
| 手机数据采集 | 默认关闭，需显式开启 | 隐私风险高，且投入产出比低 | P2 功能，可能整块砍掉 |
