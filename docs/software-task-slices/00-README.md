## 怎么用这堆任务卡

1. **先定范围**：在 [03](03-任务切片与排期.md) 里选一条切片线（A 演示级 / B 完整 MVP / C 完整体验），不要全部一起上。
2. **按依赖开工**：只领“前置依赖已全部完成”的任务。依赖关系写在每张卡顶部和 03 的总表里。
3. **认领一张卡**：把那个 `.md` 整个贴给执行者（人或 agent）即可，卡里已包含背景、约束和验收标准，不需要额外解释。
4. **验收用卡里的 checklist**：勾完才算完成。不要用“差不多能跑”作为完成标准。
5. **接口先对齐**：动手前先看该卡“需协同”列出的任务，和对方确认接口签名，再写代码。

## 五条产品原则（写给所有执行者）

1. **屏幕上永远只有一个焦点。** 单通道不是“只做一件事”，是“只显示一件事”。
2. **不给用户增加认知负荷。** 任何新功能如果让用户多做一个决定，就不该默认打开。
3. **不用惩罚制造动力。** 断更不扣分、不降级、不出现“你落后了”这类措辞。
4. **离线也要能用。** 每个依赖云的功能都必须有本地降级路径，演示现场断网是常态。
5. **先跑通一条线，再做第二条。** 宁可有 5 个功能端到端可用，不要有 15 个半截功能。
